⚙️ Cloud Optimization Specs:

  • Google BigQuery: PARTITION BY DATE(order_date) prevents full table scans; CLUSTER BY customer_id, product_id optimizes selective filtering.
  • AWS Redshift: DISTSTYLE KEY (customer_id) co-locates customer joins with worker slices; COMPOUND SORTKEY (order_date, customer_id) accelerates date range lookups.

⚡ Production SQL Queries (Recruiter Inspector)

Live queries used to compute RFM quintiles, monthly seasonality, and dimension aggregations.

-- ============================================================================= -- RFM (Recency, Frequency, Monetary) Segmentation Query with Quintile Scoring -- ============================================================================= WITH reference_date AS ( SELECT MAX(CAST(order_date AS DATE)) AS max_analysis_date FROM fact_sales ), customer_rfm_metrics AS ( SELECT c.customer_id, c.name AS customer_name, DATE_DIFF(ref.max_analysis_date, MAX(CAST(f.order_date AS DATE)), DAY) AS recency_days, COUNT(DISTINCT f.order_id) AS frequency_orders, ROUND(CAST(SUM(f.item_total) AS NUMERIC), 2) AS monetary_spend FROM dim_customers c JOIN fact_sales f ON c.customer_id = f.customer_id CROSS JOIN reference_date ref GROUP BY c.customer_id, c.name, ref.max_analysis_date ), customer_rfm_scores AS ( SELECT *, NTILE(5) OVER (ORDER BY recency_days DESC) AS r_score, NTILE(5) OVER (ORDER BY frequency_orders ASC) AS f_score, NTILE(5) OVER (ORDER BY monetary_spend ASC) AS m_score FROM customer_rfm_metrics ) SELECT customer_id, customer_name, recency_days, frequency_orders, monetary_spend, CASE WHEN r_score >= 4 AND f_score >= 4 AND m_score >= 4 THEN 'Champions' WHEN r_score >= 3 AND f_score >= 3 AND m_score >= 3 THEN 'Loyal Customers' WHEN r_score >= 4 AND f_score <= 2 THEN 'New / Promising' WHEN r_score <= 2 AND f_score >= 3 THEN 'At Risk' ELSE 'Lost Customers' END AS customer_segment FROM customer_rfm_scores ORDER BY monetary_spend DESC;
